# SDKFactory

[androidJvm]\
interface [SDKFactory](index.md)

Factory for pipeline instances. Obtain one from [EffectsSDK.createSDKFactory](../-effects-s-d-k/create-s-d-k-factory.md).

The methods come in two independent pairs of flavours.

**Full or lite.** A lite pipeline runs a graph without smart zoom, which is the only feature needing a face detection model on top of the segmentation ones, so it loads and runs one model less per frame. Everything else, including background replacement, beautification, color correction and portrait lighting, works the same. The lite factory methods take fewer arguments than the full ones, but that only sets the starting state: the options they leave out are still available through the pipeline's setters.

**Blocking or async.** Creating a pipeline builds a MediaPipe graph, loads the models and compiles the shaders, which takes long enough to be visible on the main thread. The blocking methods do that work on the calling thread. The `…Async` methods do it on a background thread shared by this factory, push one warm-up frame through the graph, and only then invoke their callback, so that by the time you get the pipeline it has already produced a frame and the first real one is not slow.

An async callback arrives on the thread the pipeline delivers frames on, never on the caller's thread, and the pipeline is handed over with no [com.effectssdk.tsvb.pipeline.OnFrameAvailableListener](../../com.effectssdk.tsvb.pipeline/-on-frame-available-listener/index.md) attached: the one used to await the warm-up frame is detached first. A camera pipeline is not started either, so call [CameraPipeline.startPipeline](../../com.effectssdk.tsvb.pipeline/-camera-pipeline/start-pipeline.md) as usual.
